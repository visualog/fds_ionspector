# 05. Page Recipes

## Docs Overview

Use for the admin dashboard/overview.

Structure:

- concise intro
- getting started or status summary
- foundation links
- component/rule/resource links
- no right TOC unless content becomes long

## Foundation Page

Use for tokens, color, typography, spacing, radius, and motion.

Structure:

- title and definition
- purpose/principles
- usage guidance
- examples or visual samples
- token table/reference
- related pages

Required:

- what it is
- why it matters
- usage principles
- tokens or examples

## Component Index

Use for component catalog pages.

Structure:

- page title
- short intro
- category groups
- compact cards or rows
- platform/status badges if useful

## Component Detail

Use for individual component documentation.

Structure:

- title
- short definition
- platform support
- anatomy
- properties
- variants
- guidelines
- accessibility
- examples
- related components

## Guidelines / Rules

Use for inspection rules and validation guidance.

Structure:

- purpose
- rule categories
- runtime owners
- tests
- do/don’t or examples when useful

Prefer tables or rows over decorative cards.

## Release / Status

Use for build and release pages.

Structure:

- build command
- output paths
- runtime file groups
- validation checklist
- related handoff documents

## Resources

Use for QA docs, plans, handoffs, reports, and verification references.

Structure:

- grouped document lists
- compact file pills
- short descriptions when needed
