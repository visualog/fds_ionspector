# 01. Principles

Use this direction as a design grammar, not a pixel-perfect clone.

## Personality

- clear
- systematic
- compact
- calm
- practical
- documentation-first
- product-design oriented
- platform-aware
- token-driven
- neutral but friendly

## Visual Mood

The interface should feel like a serious design-system documentation site.

Prefer:

- white or near-white canvas
- black and gray text hierarchy
- subtle borders
- precise spacing
- compact cards only when useful
- restrained accent color
- high readability
- clear grouping
- predictable navigation

Avoid:

- marketing hero layouts
- dark immersive sections
- giant display typography by default
- heavy shadows
- glassmorphism
- decorative blobs
- aggressive animations
- overly rounded SaaS dashboard styling

## FDS Admin Reading

The admin app is for operators and maintainers checking tokens, rules, build outputs, QA docs, and module ownership.

The design should help the user answer:

- What is managed here?
- Where is the source file?
- What rule or module owns this behavior?
- What document or release artifact should I inspect next?

Every section should reduce lookup cost.
