# FDS Inspector 프로젝트 브리프 및 FIX 발표자료 가이드

> 이 문서는 외부 발표자료 제작자 또는 프로젝트를 처음 접하는 협업자가 FDS Inspector를 이해하고, 근거 기반의 발표자료를 기획·제작할 수 있도록 만든 프로젝트 브리프다.
>
> 목적: FDS Inspector가 해결하는 검수 문제와 실제 검증 결과를 바탕으로, FIX 발표자료를 구성한다.
>
> 핵심 메시지: **FDS Inspector는 웹 화면의 디자인 시스템 준수 여부를 자동 검사하고, 위반 요소를 화면에서 바로 확인하게 해 수동 검수의 불확실성과 반복 작업을 줄이는 크롬 익스텐션이다.**

## 발표 개요

| 항목 | 내용 |
| --- | --- |
| 과제명 | FDS 디자인 시스템 준수 여부 검사 방식 개선 |
| 산출물 | FDS Inspector 크롬 익스텐션 |
| 대상 | 웹 화면을 구현·검수하는 개발자, 디자이너, QA 담당자 |
| 범위 | 컬러, 폰트, 간격, 라운드 값의 FDS 기준 준수 여부 검사 및 위반 위치 확인 |
| 제외 범위 | 운영 대시보드나 AI 도구 소개가 아닌, 브라우저 익스텐션 자체의 검수 기능에 집중 |

## 1. 프로젝트 브리프

### 1.1 프로젝트 한 줄 소개

FDS Inspector는 웹 화면의 디자인 시스템 준수 여부를 브라우저에서 검사하고, 위반 요소와 수정 위치를 화면에서 확인하게 해주는 디자인 QA용 크롬 익스텐션입니다.

### 1.2 개발 배경

웹 화면이 FDS 기준대로 구현됐는지 확인하려면 컬러, 폰트, 간격, 라운드 같은 속성값을 기준 문서와 화면에서 반복 비교해야 합니다. 이 과정은 화면 수와 릴리즈 횟수가 늘어날수록 시간이 길어지고, 담당자별 판단 차이와 누락 가능성이 생깁니다.

### 1.3 해결하려는 문제

- 수작업 속성 대조에 많은 시간이 소요됨
- 검사자마다 확인 범위와 기준 해석이 달라질 수 있음
- 위반 결과를 발견한 뒤 실제 화면의 수정 대상을 다시 찾아야 함
- 검사 결과의 범위와 상태를 한눈에 파악하기 어려울 수 있음

### 1.4 프로젝트 목표

- FDS 기준과 실제 웹 화면 속성을 자동 비교한다.
- 컬러, 폰트, 간격, 라운드 위반 결과를 유형별로 제시한다.
- 결과 목록에서 실제 DOM 요소와 Inspector 정보까지 바로 연결한다.
- 반복 검수에 필요한 확인·탐색 작업을 줄이고, 동일한 기준의 품질 관리를 돕는다.

### 1.5 핵심 기능

| 기능 | 하는 일 | 발표에서 전달할 의미 |
| --- | --- | --- |
| 디자인 토큰 검사 | 컬러·폰트·간격·라운드 값과 FDS 기준을 비교 | 기준에 따른 자동 검수 |
| 결과 분류 | 검사 유형별 위반 결과를 분리해 표시 | 문제를 빠르게 이해하는 구조 |
| DOM 하이라이트 | 결과 항목 선택 시 실제 화면 요소를 강조 | 수정 대상을 다시 찾는 시간을 줄임 |
| Inspector 정보 | 해당 요소의 속성, 위반 사유, 대체 토큰 후보 확인 | 발견한 문제를 수정으로 연결 |
| 검사 상태 안내 | 검사 개수, 소요 시간, 일부 검사 여부 표시 | 결과의 신뢰 범위와 현재 상태를 명확히 함 |
| 리포트 저장 | 위반 요소 결과를 사람이 읽기 쉬운 HTML 리포트로 저장 | 수정 요청과 검수 이력 공유에 활용 |

### 1.6 차별화 포인트

- 단순히 위반 건수를 보여주는 도구가 아니라, **위반 결과 → 실제 화면 요소 → Inspector 정보**를 하나의 검수 흐름으로 연결합니다.
- 별도 서비스 화면으로 이동하지 않고, 검사하려는 웹 화면에서 바로 실행하는 크롬 익스텐션입니다.
- 기준 비교를 자동화하되 최종 수정 판단은 담당자가 내릴 수 있도록, 결과와 근거를 화면에서 확인하게 합니다.

### 1.7 검증된 사실과 근거

| 항목 | 확인된 사실 | 근거 문서 |
| --- | --- | --- |
| 대형 DOM 검사 | 7,502개 DOM 중 최대 6,000개를 배치 처리하여 2.0초에 검사 | `docs/verification/fds-2week-performance-and-real-use-verification.md` |
| 실제 업무 화면 | LUKE 메인에서 439/806개 요소를 13.0초에 검사 | 동일 문서 |
| 결과 탐색 | 컬러, 폰트, 간격, 라운드 결과를 분리해 탐색 | 동일 문서 |
| 화면 연결 | 결과 항목 선택 시 DOM 하이라이트와 Inspector 정보 카드 표시 | 동일 문서 및 `fds-accuracy-inspection-verification.md` |
| 정확도 개선 | 방향별 간격 표시와 동일 결과 중복 집계 방지 확인 | `docs/verification/fds-accuracy-inspection-verification.md` |

### 1.8 발표 제작자가 반드시 이해할 메시지

1. FDS Inspector는 **AI 도구가 아니라 디자인 시스템 검수용 크롬 익스텐션**입니다.
2. 사람을 대체한다고 말하기보다, 사람이 반복적으로 하던 기준 비교와 위치 탐색을 줄이는 도구로 표현합니다.
3. 발표의 중심은 기술 기능 나열보다 **문제 → 자동 검사 → 실제 화면 확인 → 검증된 효과**의 흐름입니다.
4. 연간 비용 절감액이나 시간 단축률은 실측값이 확정되기 전까지 추정 수치로 제시하지 않습니다.

## 2. 발표자료 제작 방향

### 2.1 발표 목적과 청중

| 항목 | 권장 방향 |
| --- | --- |
| 발표 목적 | FIX 과제가 어떤 문제를 해결했고, 실제로 어떻게 동작하며, 조직에 어떤 가치를 줄 수 있는지 설득 |
| 주요 청중 | 사내 심사자, 리더, 개발·디자인·QA 협업자 |
| 청중이 이해해야 할 결론 | FDS Inspector는 디자인 시스템 검수를 더 일관되고 재현 가능하게 만드는 실무 도구 |
| 권장 이야기 구조 | 문제 정의 → 해결 방법 → 차별성 → 실제 검증 → 업무 가치 → 산정 근거 |

### 2.2 슬라이드에 반드시 포함할 내용 중심

| 우선순위 | 포함할 내용 | 설명 |
| --- | --- | --- |
| 1 | 수동 검수의 문제 | 왜 이 도구가 필요한지: 시간, 기준 일관성, 위치 탐색 문제 |
| 2 | 자동 검사 흐름 | 화면 분석부터 기준 비교, 결과 분류, DOM 강조까지의 흐름 |
| 3 | 실제 화면 증빙 | 검사 결과 패널, DOM 하이라이트, Inspector 정보 카드 |
| 4 | 검증 결과 | 대형 DOM·실제 업무 화면에서 확인된 성능과 동작 |
| 5 | 차별성 | 결과 목록만이 아니라 수정 대상까지 연결하는 방식 |
| 6 | 업무 가치 | 수작업 비교와 탐색 감소, 동일 기준의 QA, 적용 확장성 |
| 7 | 가치 산정 근거 | 실제 시간·횟수·인원·원가를 입력하는 투명한 산식 |

### 2.3 권장 시각 자료

- 대형 DOM 검사 전·후 결과 패널 캡처
- 컬러, 폰트, 간격, 라운드별 결과 화면
- 결과 항목 선택 후 DOM 하이라이트와 Inspector 정보 카드가 함께 보이는 화면
- 웹 화면 분석 → FDS 기준 비교 → 위반 결과 분류 → 화면 요소 강조의 4단계 흐름도
- 수작업 검수와 Inspector 활용 검수의 비교 구조
- 가치 산정 수식과 실제 입력값을 넣을 수 있는 템플릿

### 2.4 디자인·톤앤매너

- 전문적이고 명료한 디자인 시스템·품질 검수 도구의 인상
- 밝은 배경, FDS 계열의 블루·그린을 핵심 강조색으로 사용
- 대시보드나 카드 UI처럼 복잡하게 꾸미기보다, 실제 검사 화면과 검증 근거를 중심으로 구성
- 한 장에 하나의 핵심 주장만 두고, 숫자는 맥락과 함께 제시

### 2.5 반드시 피할 표현

- “AI 기반”, “AI가 검수한다”
- “100% 자동”, “모든 오류를 발견”, “완벽한 검수”
- 실제 측정값 없는 비용 절감 금액·절감률
- 모든 사이트·모든 환경에서 동일하게 동작한다는 보장 표현

### 2.6 제작 전 추가로 확보하면 좋은 정보

- 발표 대상 서비스의 실제 FDS Inspector 검사 화면 캡처
- 대표 화면별 기존 수동 검수 시간과 Inspector 활용 검수 시간
- 월 평균 검수 횟수와 실제 검수 참여 인원
- 과제 ID, 등록일, 발표자·참여자 정보
- 최종 발표 시간과 심사 기준

### 발표 멘트

FDS Inspector는 웹 화면이 FDS 디자인 시스템 기준에 맞게 구현되었는지 빠르게 확인하기 위한 크롬 익스텐션입니다. 수동으로 화면 속성을 대조하던 검수 과정을 자동화하고, 문제가 있는 실제 화면 요소를 바로 확인할 수 있도록 만들었습니다.

## 슬라이드 2. 주요 용어 정의

### 슬라이드에 넣을 내용

| 용어 | 설명 |
| --- | --- |
| FDS | 웹 화면 구현의 기준이 되는 디자인 시스템 |
| 디자인 토큰 | 컬러, 폰트, 간격, 라운드 등 UI 속성의 표준 값 |

### 발표 멘트

이 발표에서는 FDS를 화면 구현의 공통 기준으로, 디자인 토큰을 그 기준을 구성하는 속성값으로 사용합니다. FDS Inspector는 이 기준과 실제 웹 화면의 DOM·스타일 값을 비교하여 위반 요소를 찾는 도구입니다.

## 슬라이드 3. 문제 정의

### 핵심 문장

**수동 검수만으로는 화면별 디자인 시스템 준수 여부를 빠르고 일관되게 확인하기 어렵습니다.**

### 슬라이드에 넣을 내용

- 컬러·폰트·간격·라운드 값을 사람이 화면과 기준 문서에서 하나씩 대조해야 함
- 검사자, 화면, 릴리즈 상황에 따라 확인 기준과 누락 가능성이 달라짐
- 문제 결과가 실제 화면의 어느 요소인지 다시 찾는 과정이 반복됨

### 해결해야 하는 이유

- 릴리즈 전 검수 시간이 길어질 수 있음
- 같은 기준을 적용해도 결과의 일관성이 떨어질 수 있음
- 디자인 시스템 위반 요소가 누락되면 UI 품질 편차가 누적될 수 있음

### 발표 멘트

기존 검수는 사람이 화면과 디자인 기준을 오가며 속성값을 비교하는 방식이었습니다. 이 방식은 화면 수가 늘어날수록 시간이 많이 들고, 검사자마다 확인 범위가 달라질 수 있습니다. 따라서 기준 비교와 위반 위치 확인을 하나의 흐름으로 연결할 필요가 있었습니다.

## 슬라이드 4. 해결 방법 소개

### 핵심 문장

**웹 화면을 분석하고 FDS 기준과 비교한 뒤, 위반 결과를 화면 요소와 연결합니다.**

### 검사 흐름

```text
웹 화면 분석
    ↓
FDS 기준 비교
    ↓
위반 결과 분류
    ↓
화면 요소 강조 및 Inspector 정보 확인
```

### 슬라이드에 넣을 내용

- 컬러, 폰트, 간격, 라운드 값을 검사
- 검사 결과를 유형별로 분류
- 결과 항목을 선택하면 실제 DOM 요소를 화면에서 하이라이트
- 요소의 속성·위반 사유·대체 토큰 후보를 Inspector 정보로 확인

### 발표 멘트

FDS Inspector는 브라우저에서 현재 화면을 분석하고, FDS 기준과 다른 속성을 위반 결과로 분류합니다. 단순히 결과 목록만 보여주지 않고, 결과를 선택하면 실제 화면 요소가 강조되어 수정 대상과 원인을 빠르게 확인할 수 있습니다.

## 슬라이드 5. 창의성 및 차별성

### 핵심 문장

**검수 결과를 숫자 목록으로 끝내지 않고, 수정해야 할 실제 화면 요소까지 연결합니다.**

### 비교 내용

| 구분 | 내용 |
| --- | --- |
| 기존 수동 검수 | 화면과 기준 문서를 보며 속성값을 개별 확인 |
| FDS Inspector | 브라우저에서 기준을 자동 비교하고 위반 위치를 즉시 강조 |
| 차별점 | 결과 목록, DOM 하이라이트, Inspector 정보를 한 흐름으로 연결 |

### 확장성 관점

- 디자인 토큰과 검사 기준을 재사용해 다른 웹 서비스에도 적용 가능
- 릴리즈 전 점검, 디자인 QA, 개선 작업 확인 등 다양한 검수 시나리오에 활용 가능
- 검사 결과를 리포트 형태로 저장하여 수정 요청·이력 관리에 활용 가능

### 발표 멘트

핵심 차별점은 자동 검사 자체보다, 검사 결과를 실제 화면의 수정 대상과 직접 연결한 점입니다. 검수자는 결과를 보고 다시 화면에서 요소를 찾는 대신, 결과 선택만으로 위치와 원인을 확인할 수 있습니다.

## 슬라이드 6. 개선 효과 및 검증 결과

### 핵심 문장

**대형 화면과 실제 업무 페이지에서 검사 흐름, 결과 탐색, 하이라이트 동작을 확인했습니다.**

### 검증 결과

| 검증 항목 | 확인 결과 |
| --- | --- |
| 대형 DOM 검사 | 7,502개 DOM 중 최대 6,000개를 배치 처리하여 2.0초에 검사 |
| 실제 업무 화면 | LUKE 메인 화면에서 806개 요소를 13.0초에 검사 완료 |
| 검사 범위 표시 | 완료 상태에 검사 개수, 소요 시간, 일부 검사 여부 표시 |
| 결과 탐색 | 컬러·폰트·간격·라운드 결과를 유형별로 확인 |
| 화면 연결 | 결과 항목 선택 시 실제 DOM 하이라이트와 Inspector 정보 카드 표시 |

### 개선된 사용자 경험

- 위반이 없는 항목이 먼저 선택되어 실제 문제가 숨겨지는 흐름 개선
- 검사 항목 전환 시 이전 항목의 강조 상태가 남지 않도록 정리
- 오류 발생 시 로딩 문구가 남지 않고 오류 상태를 표시하도록 개선

### 발표 멘트

대형 DOM 환경에서는 브라우저가 멈추지 않도록 배치 처리 흐름을 확인했고, 실제 업무 페이지에서도 검사 완료와 결과 탐색이 동작하는 것을 검증했습니다. 특히 결과가 실제 DOM 요소와 연결되어, 검수자가 수정 대상을 빠르게 찾을 수 있도록 했습니다.

## 슬라이드 7. 가치

### 핵심 문장

**수작업 대조와 위치 탐색을 줄이고, 동일한 기준으로 웹 UI 품질을 관리할 수 있습니다.**

### 가치 설명 모델

| 구분 | 내용 |
| --- | --- |
| Benefit | 수작업 비교·위치 탐색 감소, 검수 기준 일관성 확보, UI 품질 편차 감소 |
| Cost | 기존 Chrome 환경에서 사용하는 확장 프로그램이며, 운영·유지 비용은 별도 산정 필요 |
| Scalability | 다른 웹 서비스·화면·릴리즈 검수 시나리오로 적용 범위 확장 가능 |

### 연간 가치 금액

`[실제 검수 횟수 및 인건비 기준으로 산정 후 입력]`

### 발표 멘트

FDS Inspector의 직접 가치는 검수에 드는 수작업 비교와 위반 위치 탐색을 줄이는 데 있습니다. 또한 담당자가 달라도 동일한 FDS 기준으로 결과를 확인할 수 있어, 장기적으로는 서비스 간 UI 품질 편차를 낮추는 데 기여할 수 있습니다.

## 슬라이드 8. 가치 산정 수식

### 산정 원칙

**검수 시간 절감액을 기준으로 연간 가치를 계산합니다.**

```text
연간 절감 가치
= (기존 수동 검수 시간 − Inspector 활용 검수 시간)
  × 월 검수 횟수
  × 12개월
  × 검수 참여 인원
  × 시간당 인건비
```

### 제출 전 입력할 값

| 입력값 | 확인 방법 |
| --- | --- |
| 기존 수동 검수 시간 | 대표 화면 유형별 평균 검수 시간을 측정 |
| Inspector 활용 검수 시간 | 같은 화면을 Inspector로 검수한 시간을 측정 |
| 월 검수 횟수 | 릴리즈·QA·개선 작업의 평균 횟수 확인 |
| 검수 참여 인원 | 개발·디자인·QA의 실제 참여 인원 확인 |
| 시간당 인건비 | 조직의 표준 원가 또는 인건비 기준 적용 |

### 발표 멘트

현재 검증 자료에는 검사 성능과 기능 동작 결과가 포함되어 있습니다. 금액은 추정으로 제시하지 않고, 실제 화면 유형과 검수 운영 데이터를 수집한 뒤 이 수식으로 산정하는 것이 적절합니다.

## 마무리 메시지

FDS Inspector는 디자인 시스템 검수를 사람의 기억과 수작업 대조에만 의존하지 않도록 돕는 크롬 익스텐션입니다. 자동 기준 비교, 결과 분류, 화면 하이라이트를 연결하여 **문제 발견부터 수정 대상 확인까지의 검수 흐름을 단축**합니다.
