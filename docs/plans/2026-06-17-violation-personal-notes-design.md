# Violation Personal Notes Design

작성일: 2026-06-17

## Goal

FDS Inspector 위반 요소에 개인 작업 메모를 남기고, 같은 페이지를 다시 열었을 때 메모가 있는 위반 항목을 다시 확인할 수 있게 한다.

## Scope

1차 범위는 개인 로컬 메모다. 메모는 현재 브라우저의 `chrome.storage.local`에만 저장한다. 팀 공유, 서버 동기화, 리포트 export, 페이지 아무 곳에 꽂는 자유 핀은 이번 범위에서 제외한다.

## User Flow

1. 사용자가 컬러/폰트/간격/라운드 위반 목록의 하위 항목을 클릭한다.
2. 화면이 해당 요소로 이동하고 핀과 인스펙터 카드가 표시된다.
3. 카드 하단의 `메모 추가` 버튼을 누른다.
4. 짧은 메모 입력 영역이 카드 안에 열린다.
5. 저장하면 카드와 목록 항목에 메모 있음 상태가 표시된다.
6. 같은 URL에서 다시 검사하면 가능한 한 같은 위반 항목에 메모 상태가 복원된다.
7. 사용자는 카드에서 메모를 수정하거나 삭제할 수 있다.

## Data Model

메모 저장 키는 페이지와 위반 항목을 함께 식별한다.

```js
{
  pageKey: normalizedUrl,
  noteKey: stableIssueFingerprint,
  category: "color",
  message: "배경색 rgba(0, 0, 0, 0.04) (미등록)",
  elementLabel: "div.css-2xl70c",
  text: "디자인팀에 반투명 토큰 등록 확인",
  createdAt: "2026-06-17T00:00:00.000Z",
  updatedAt: "2026-06-17T00:00:00.000Z"
}
```

`pageKey`는 URL에서 hash를 제외한 값으로 시작한다. `noteKey`는 현재 `issueEntry.key`에 더해 category, colorPart, message, element label/class 기반 정보를 조합한다. DOM이 크게 바뀐 경우 완벽 복원은 보장하지 않고, 같은 페이지에서 같은 검사 결과가 나오는 일반 케이스를 우선한다.

## UI Design

인스펙터 카드에는 기존 위반 정보 아래에 작은 메모 영역을 추가한다. 메모가 없으면 `메모 추가` 버튼만 보인다. 메모가 있으면 한 줄 미리보기, `수정`, `삭제` 액션을 표시한다.

위반 목록의 하위 항목에는 메모가 있는 경우 작은 점 또는 `메모` 배지를 붙인다. 기존 목록의 밀도가 높으므로 긴 텍스트는 목록에 직접 노출하지 않는다.

핀은 기존 번호 핀을 유지하되, 메모가 있는 핀에는 `has-note` 상태 클래스를 붙여 작은 표시를 추가한다. 메모 때문에 새로운 핀 레이어를 만들지는 않는다.

## Architecture

`content.js`가 현재 위반 항목 상태, 핀, 인스펙터 카드 표시를 조율하고 있으므로 1차 구현도 이 흐름 안에 붙인다. 저장/조회 로직은 작은 helper 함수로 분리하되, 별도 서버나 background 메시징은 만들지 않는다.

`content-render.js`는 목록 항목 마크업에 메모 상태를 반영하는 정도만 맡긴다. 카드 메모 UI는 현재 카드가 `content.js`에서 직접 구성되고 있으므로 우선 같은 위치에 둔다. 이후 카드 렌더러 분리 시 함께 이동할 수 있다.

## Error Handling

`chrome.storage.local`을 사용할 수 없거나 저장에 실패하면 카드 안에 짧은 오류 문구를 보여준다. 저장 실패 시 기존 메모 상태는 바꾸지 않는다. 저장소 데이터가 깨져 있으면 빈 메모 상태로 복구하고 콘솔 경고만 남긴다.

## Testing

기존 저장소 패턴에 맞춰 `content-scan-runner.test.js`의 소스 레벨 회귀 테스트를 먼저 추가한다. 저장 helper가 별도 모듈로 빠질 경우 해당 모듈 단위 테스트를 추가한다.

핵심 검증 항목:

- 인스펙터 카드에 메모 추가/수정/삭제 UI가 연결된다.
- 메모 저장에는 `chrome.storage.local`이 사용된다.
- 같은 URL과 같은 위반 fingerprint에서 메모 상태가 복원된다.
- 목록 하위 항목과 핀에 메모 있음 상태가 표시된다.
- 저장 실패 시 카드가 닫히거나 선택 상태가 사라지지 않는다.

## Open Risks

- CSS-in-JS 클래스가 빌드마다 바뀌면 noteKey 복원률이 낮아질 수 있다.
- 같은 클래스/같은 위반 메시지가 여러 요소에 반복되는 경우 완벽히 하나만 식별하기 어렵다.
- 카드 UI가 너무 복잡해질 수 있으므로 1차에서는 짧은 textarea와 최소 액션만 둔다.
