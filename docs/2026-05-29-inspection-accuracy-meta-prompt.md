# FDS Inspector 검사 정확도 검수 메타 프롬프트

## 목표

FDS Inspector의 검사 정확도와 결과 표시 신뢰도를 검수하고 개선한다.

현재 발견된 `상단 패딩 14px` 오표시 문제처럼, 실제 CSS 값과 Inspector 결과 문구가 다르게 보이거나 같은 화면 요소가 여러 건으로 중복 표시되는 문제를 체계적으로 찾아 수정한다.

## 배경

LUKE 실제 업무 페이지 검증 중 DevTools 박스 모델에서는 상하좌우 패딩이 모두 `14px`인데, FDS Inspector는 `상단 패딩 14px`으로 표시했다.

이 문제는 단일 버그가 아니라 다음 영역에서 비슷하게 반복될 수 있다.

- 검사 값 판별 로직
- 결과 문구 생성 로직
- 결과 그룹/개수 표시 로직
- 같은 화면 요소를 구성하는 중첩 DOM 중복 집계
- 실제 화면 하이라이트와 결과 항목의 대응 관계

## 작업 범위

### 1. 현재 상태 확인

- 현재 변경사항과 작업트리 상태를 확인한다.
- 이미 수정된 `패딩 14px` 관련 변경이 있는지 확인한다.
- 기존 테스트 통과 상태를 확인한다.
- 기존 사용자 변경사항은 되돌리지 않는다.

### 2. 실제 페이지 샘플 검수

Chrome 또는 Computer Use로 `https://luke.fasoo.com/main` 실제 업무 페이지에서 FDS Inspector를 실행한다.

다음 검사 항목별로 결과를 샘플링한다.

- 컬러 검사
- 폰트 검사
- 간격 검사
- 라운드 검사

각 검사에서 대표 결과 항목을 최소 5개 이상 클릭하고, 실제 화면/DevTools 값과 FDS Inspector 표시값을 비교한다.

확인할 내용:

- 실제 CSS 값과 표시 문구가 일치하는가
- 패딩/마진 방향이 정확히 표시되는가
- 전체 패딩인데 `상단 패딩`처럼 잘못 표현되지 않는가
- 복합 border-radius 값이 정확히 표현되는가
- 컬러가 BG/Border/Text로 정확히 분리되는가
- 같은 화면 요소가 여러 DOM 때문에 중복 표시되는가
- 결과 항목 클릭 시 하이라이트가 사용자가 이해할 수 있는 위치에 표시되는가
- `3곳`, `29건` 같은 숫자가 사용자가 오해하지 않게 표현되는가

### 3. 문제 유형 분류

발견한 문제를 아래 유형으로 분류한다.

- 값 오판: 실제 CSS 값과 검사 결과가 다름
- 방향 오판: top/right/bottom/left 또는 전체값 표현이 틀림
- 중복 집계: 같은 시각 요소가 여러 건으로 표시됨
- 문구 오해: 숫자나 상태 문구가 사용자에게 헷갈림
- 하이라이트 문제: 결과 항목과 실제 화면 위치 연결이 불명확함
- 성능 문제: 실제 업무 페이지에서 검사 시간이 과도하거나 UI가 멈춤
- 기타 버그

### 4. 우선순위 지정

다음 기준으로 우선순위를 정한다.

1. 사용자가 잘못된 결론을 내릴 수 있는 문제
2. 결과 개수나 위반 위치를 크게 왜곡하는 문제
3. 실제 업무 페이지에서 자주 보이는 문제
4. 배포 전 신뢰도에 영향을 주는 문제
5. 단순 문구 개선

우선 처리 대상:

- 동일 위치/동일 메시지 중복 표시 정리
- 패딩/마진 방향별 표시 정확도 보강
- `3곳` 같은 표현을 사용자 기준으로 명확하게 변경
- 라운드 복합값 표시 정확도 확인
- 컬러 BG/Border/Text 분리 정확도 확인

### 5. 테스트 우선 추가

수정 전 반드시 실패하는 테스트를 먼저 작성한다.

테스트 위치 예시:

- `content-inspection.test.js`
  - CSS 값 판별 테스트
  - 패딩/마진 방향별 문구 테스트
  - 복합 라운드 값 테스트
- `content-render.test.js`
  - 결과 문구 파싱 테스트
  - 패널 표시 문구 테스트
  - 그룹 문구 테스트
- `content-scan-runner.test.js`
  - 동일 key 중복 entry가 다시 추가되지 않는지 테스트
  - 같은 시각 요소 또는 동일 signature 이슈가 어떻게 묶이는지 테스트

필요 시 fixture를 추가한다.

- `docs/verification/spacing-direction-fixture.html`
- `docs/verification/duplicate-dom-issue-fixture.html`
- `docs/verification/radius-composite-fixture.html`

각 테스트는 먼저 실패하는 것을 확인한 뒤 구현한다.

### 6. 구현

기존 구조와 스타일을 유지하며 최소 범위로 수정한다.

수정 후보:

- `content-inspection.js`
  - 패딩/마진 방향별 값 판별 개선
  - 전체값과 방향값 문구 분리
  - 복합 radius 값 처리 검토
- `content-render.js`
  - 새 검사 문구 파싱 규칙 추가
  - 결과 그룹 문구를 사용자 기준으로 명확히 변경
- `content-scan-runner.js`
  - 중복 entry push 방지
  - 동일 key 또는 동일 위치/메시지 결과 정리
- `content.js`
  - 하이라이트/Inspector 카드에서 대표 이슈와 내부 DOM 이슈 구분
  - 필요 시 결과 개수 표시 로직 조정

### 7. 실제 화면 재검증

수정 후 다음을 다시 확인한다.

- LUKE 실제 업무 페이지에서 간격 검사 실행
- `패딩 14px`처럼 전체 패딩인 경우 정확히 표시되는지 확인
- 같은 시각 요소가 여러 건으로 보이는 경우, 사용자가 오해하지 않게 표시되는지 확인
- 컬러/폰트/간격/라운드 패널 전환이 정상 동작하는지 확인
- 결과 항목 클릭 시 하이라이트와 Inspector 카드가 정상 표시되는지 확인
- 브라우저가 멈추지 않는지 확인

가능하면 Before/After 캡처를 남긴다.

### 8. 검증 명령

최소 다음 명령을 실행한다.

```bash
node --check content.js
node --check content-inspection.js
node --check content-render.js
npm test
```

필요 시 추가 테스트 파일을 직접 실행한다.

```bash
node --test content-inspection.test.js content-render.test.js content-scan-runner.test.js
```

### 9. 산출물

작업 완료 후 다음을 남긴다.

- 수정된 코드
- 추가/수정된 테스트
- 실제 화면 검증 결과
- 발견한 문제 유형 표
- 해결한 문제와 남은 문제 구분
- 필요 시 Fabric 노트 업데이트

## 완료 기준

다음 조건을 모두 만족해야 완료 처리한다.

- 실제 CSS 값과 Inspector 표시 문구가 일치한다.
- 전체 패딩/방향 패딩이 정확히 구분된다.
- 동일 이슈 중복 표시가 줄거나, 사용자에게 명확히 설명된다.
- 컬러/폰트/간격/라운드 결과가 서로 섞이지 않는다.
- 결과 항목 클릭 시 실제 문제 위치를 이해할 수 있다.
- 자동 테스트가 모두 통과한다.
- 실제 업무 페이지에서 재검증을 완료했다.
- 남은 리스크가 있다면 명확히 문서화했다.

## 주의사항

- 기존 사용자 변경사항을 되돌리지 않는다.
- 검증 없이 완료 처리하지 않는다.
- Chrome backend가 연결되지 않으면 Computer Use로 실제 화면 검증을 진행한다.
- 발견한 문제를 단순히 문구로 덮지 말고, 실제 검사 기준이 맞는지 확인한다.
- 비개발자가 봐도 이해할 수 있게 결과를 정리한다.
